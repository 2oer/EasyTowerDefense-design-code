# 代码架构设计

> 用途:记录**每项功能实际实现时使用哪个代码模块**,作为编码阶段的施工图。
> 原则:**数值全部来自配置表**(对应 `thought.md` 的表格),代码只负责结算规则;`DPS / 出勤率 / 有效DPS` 属于设计期验收口径,**不参与运行时**。

---

## 〇、技术选型与硬约束

| 项 | 选择 | 理由 |
|---|---|---|
| 引擎 | **Unity 2022 LTS(C#)**;2D 俯视 | 数百单位 + 轻量几何画风;若改用 Godot,C# 核心层可原样搬过去,只重写表现层 |
| 逻辑帧率 | **固定 30 Hz**(`dt = 1/30`) | 文档里最小的时间量是 0.2 s(阻滞清除)、0.3 s(扫射停火),30 Hz 足够 |
| 逻辑/表现 | **核心层纯 C#,不引用 `UnityEngine`** | 可脱离引擎跑单测与 `SimHarness` |
| 随机 | **自带种子 RNG(PCG/xorshift)** | 复现、可回归测试;核心层禁止 `UnityEngine.Random` |
| 配置 | **JSON 权威源 + 启动期校验**;Editor 侧可选 ScriptableObject 包装 | `SimHarness` 与游戏读同一份表,避免两套数值 |
| 单位 | 世界单位 = 文档单位(战场 80×120);向量用自带 `Vec2` | 不引入 UnityEngine 依赖 |

> 逻辑与表现的比例:**逻辑层不产生任何 GameObject**;表现层只做“读快照 → 插值 → 播特效”。

## 一、分层与依赖规则

```
App(启动 / 暂停 / 存档)
   ↓
Presentation(Unity: View / VFX / HUD)      ← 只读 Battle 快照
   ↓
Battle(波次 / 经济 / 升级 / 命令 / 统计 / BattleSimulation 主循环)
   ↓
Entity(敌人 / 塔 / 弹体 / 无人机 / 移动工厂)   →   Targeting / Combat
   ↓
Combat(护甲 / 衰减 / 贯穿 / 阻滞 / 状态)      Targeting(权重 / 选择 / 枪线)
   ↓
Model(五个库 + 加载 + 校验)
   ↓
Core(数学 / 随机 / 池 / 空间网格 / 事件)
```

**依赖铁律**
1. `Core` 不依赖任何层;`Model` 只依赖 `Core`;`Combat` 依赖 `Model + Core`。
2. `Entity` 可以读 `Model`,**不能读 `Battle`**;跨实体交互一律走 `EntityWorld` 查询或事件。
3. `Presentation` **禁止写逻辑**:只读 `BattleSimulation` 的只读快照,所有输入转为 `BattleCommand`。
4. 同层模块之间只通过接口或 `EntityWorld` 交互,禁止互相 `new` 具体实现(塔的行为用 `ITowerBehavior` 注入)。

## 三、核心类型

```csharp
// ---------- 标识与数学 ----------
public readonly struct EntityId : IEquatable<EntityId> { public readonly int Index; public readonly int Generation; }
public readonly struct Vec2 { public readonly float X, Y; /* + - * dot len normalize distance */ }

// ---------- 伤害包(唯一入口) ----------
public enum DamageType { Ballistic, Energy, Explosive, Elemental, Radiation }
public enum ArmorPierce { Low, Mid, High }          // 低 / 中 / 高级穿甲
public enum ArmorClass  { Low, Mid, Heavy }         // 低级 / 中级 / 重型护甲
public enum PenetrationMode { RetentionBased, InfiniteUntilLarge, None }

public struct DamagePacket {
    public float Amount;
    public DamageType Type;
    public ArmorPierce Pierce;
    public PenetrationMode Penetration;
    public float Retention;          // 仅 RetentionBased 读取
    public float BlockForce;         // 阻滞力(0 = 无)
    public float ExplosionRadius;    // >0 时按爆炸结算
    public StatusApply[] Statuses;   // 小数组,池化
    public EntityId Source;
    public bool IsDot;               // 属性 DoT:衰减按一半计
}
```

**约定**:任何伤害只能走 `DamageCalculator.Apply(packet, target, ctx)`,不允许在实体里手写 `hp -= x`。

## 四、数据层 `Model`(五个库)

| 库 | 放什么 | 明确不放 |
|---|---|---|
| **防御塔库** | `TowerDef`、升级树**引用**、默认投射物 id、行为类型 | 升级数值(只在升级库) |
| **投射物库** | **贴图 / 音效 key**、`delivery`、弹速、寿命、爆炸半径、追踪、`fuseDistance` | **任何伤害数值**(发射瞬间从塔拷贝) |
| **敌人库** | `EnemyDef`、分裂子代 `childId / 数量 / 生命比例` | 波次数量 |
| **地图库** | `MapDef`:尺寸、`slots[]`、基地坐标、地形 tag | 空位数(**由 `slots.Length` 推导**) |
| **升级库** | Lv2–Lv7 **全部**节点 `{StatKey, Op, Value}` + `BehaviorPatch` | 塔的基础面板 |

**实现要点**
- 属性修正统一为 `{ StatKey, Op(Add|Mul), Value }` 的列表,逐级**累乘**(文档“增幅一律乘算”)。
- `StatKey` 是枚举(约 40 个):`Damage, FireRate, Range, TurnSpeed, BlockForce, Pierce, Retention, Ammo, ReloadTime, BurstCount, BeamWidth, ExplosionRadius, ProjectileSpeed, Accuracy, Scatter, DroneDamage, DroneCount, DroneAmmo, DroneRange, DroneSpeed, HangarCapacity, LaunchInterval, MissileCount, SelfDestructRadius, DamageTaken…`
- `BehaviorPatch` 处理**换形态**升级(聚焦/扫荡/蜂窝/发射井/极光/雷暴/精装修/大舰巨炮):指定 `newBehaviorType + 覆盖参数`,由 `TowerStatsBuilder` 在升级完成时替换 `ITowerBehavior`。
- `ModelValidator` 在启动期硬校验:引用的 id 存在、区间合法、升级带宽在 `+35%~+50%`(对群/辅助白名单例外)、**换形态唯一升级按 `max(单体, 对群) ∈ [+35%, +50%]` 且另一项 ≥ `+10%`**、球形闪电对群按 `+35%~+70%` 白名单、`容量 % 编队 == 0`、`0.5 s 结算间隔`、**无人机塔的升级节点不得出现 `TurnSpeed` / `AimTolerance`**(见 6.7)等;不通过直接抛错,不带病运行。

### 4.1 三层数据与缓存失效

| 层 | 归属 | 内容 | 生命周期 |
|---|---|---|---|
| `TowerRuntimeStats` | 每座塔 | 伤害、射速、射程、转向、载弹、留存、穿甲、阻滞、爆炸半径… | 布防结束 / 升级 / 干扰变化时重建 |
| `ProjectileTemplate` | 每座塔 | 由上面的**伤害子集**派生:**目标无关**的数值 | 同上 |
| `ProjectileInstance` | 全局池 | 位置、方向、寿命、z/vz、模板引用 | 火箭塔 / 迫击炮 / 无人机 |

- **发射 = 拷贝模板**:`Rent()` → 按值拷贝 `ProjectileTemplate` → 叠加本发散射 → 填位置。不做属性换算、不分配。
- **命中才算目标侧乘区**:护甲、易伤、减伤、热熔 / 碎甲 / 低温都必须按**目标**现算——同一发子弹打铁壁和磁暴数值不同,不能缓存。
- **失效用版本号而不是枚举来源**:`StatsVersion++` 挂在布防结束、升级、拆除、干扰施加 / 叠层 / 到期 / 死亡驱散上,发射前比对一次。
- **明确不缓存**:散射、剩余留存、已命中集合、飞行寿命、任何目标相关乘区。
- **hitscan 无实例**:直接消费模板,不 Rent、不入池。

## 五、结算层 `Combat`

### 5.1 `DamageCalculator`(顺序即规则)

```csharp
public static float Apply(in DamagePacket p, EnemyRuntime e, BattleContext ctx)
{
    if (p.Type == DamageType.Radiation) return p.Amount;             // 100%,不吃护甲/衰减/特效
    float armor  = ArmorTable.Get(p.Pierce, e.Armor, e.HasStatus(ArmorBreak));
    float decay  = p.Type switch {
        DamageType.Explosive => e.ExplosiveDecay,
        DamageType.Elemental => e.ElementalDecay * (p.IsDot ? 0.5f : 1f),
        _ => 0f                                                       // 实弹/能量:衰减只扣留存,不减伤
    };
    float vuln   = Vulnerability(e, p.Type);                          // 大型专属:对应衰减 <3.0 → ×1.5
    float effect = 1f;                                                // 热熔易伤等
    float reduce = e.InAura(ShieldReduce) ? 0.75f : 1f;               // 独立乘区
    return p.Amount * armor * (1f - decay) * vuln * effect * reduce;
}
```

- **护甲**:`ArmorTable.Get(pierce, armor, armorBroken)` — 同级 100%、高一级 50%(碎甲 70%)、高两级 0%(碎甲 20%)、低一级 120%。
- **易伤**:只对 `vulnerabilityAxis` 匹配的**实弹/能量**生效(大型变体属性);爆炸/属性不走易伤,避免“0% 衰减 = 必吃 50%”的错误。
- **减伤**:护盾调度单元的 25% 为独立乘区,与护甲、衰减**乘算**。
- **热熔**:激光束命中叠加,上限 ×2.5,由 `StatusSystem` 提供 `effect`。

### 5.2 `PenetrationResolver`(三种模式)

| 模式 | 规则 | 使用者 |
|---|---|---|
| `RetentionBased` | 由近到远,**加法扣减**,剩余 <1 消失,伤害**不衰减** | 机枪、激光、电弧(无留存则不贯穿) |
| `InfiniteUntilLarge` | **不读留存**:无限穿透小/中,**命中第一只大型即停**;掠过中小型 ×50% 且**只结算横向第一排**(小型 7 / 中型 4);大型 ×125%(能量易伤再 ×1.5) | 阳电子炮 |
| `None` | 命中即止 | 无贯穿弹种 |

横向命中数统一走 `1 + ⌊束宽 ÷ 体型宽度⌋`;几何查询由 `HitscanQuery` 负责,扣减与结算交给本模块。

### 5.3 `BlockResolver`
`≤阈值` 无效;`(阈值, 2×阈值]` 减速 `(f−阈值)/阈值`;`>2×阈值` 击退(上限 25% 移速);**0.2 s 未受击清除**。低温把阈值按 `−5%/−10%/−10%` 递减。

### 5.4 `StatusSystem`
统一状态容器:`{ id, stacks, expiry, nextTick, sourceStats }`。`Burn` 每 1 s 结算 DoT(属性衰减按一半);`Charge` 死亡时引爆;`LowTemp` 改阈值与属性衰减;`ArmorBreak` 改跨级系数;`HeatMelt` 只被激光束读取。

### 5.5 `HitscanResolver`(取代绝大多数弹体)

| 原语 | 判定 | 用途 |
|---|---|---|
| `CapsuleHit` | `dist(center, segment) ≤ halfWidth + radius` | 子弹、激光、阳电子炮 |
| `CircleHit` | `dist(center, point) ≤ radius + bodyRadius` | 爆炸、近炸、光环 |

- **必须用“中心 + 半径”**:小型 0.5 / 中型 1.0 / 大型 7.5(体积上限 1×1 / 2×2 / 15×15)。只有这样,束宽 6 才正好覆盖 **小型 7 个 / 中型 4 个**,与 `1 + ⌊束宽 ÷ 体型宽度⌋` 完全一致;按点判定会少一格。
- 命中列表按**沿射线的投影距离**排序,按 `EntityId` 去重,再交给 `PenetrationResolver`。
- `HitscanNearFuse`:首个交点沿方向前移 `fuseDistance`(必须 **< 爆炸半径**),以该点为圆心做 `CircleHit`,**原目标保底受击**。
- `Chain`:先算 3 跳命中,再交给表现层画折线。
- **无实例、无池、无命中集合**;曳光终点 = 最后贯穿到的敌人,穿完则到射程末端。
- 为什么能砍:机枪 125 速 / 35 射程 = 0.28 s,敌人 0.22~0.48/s 只位移 **0.06~0.13**,小于小型半径 0.5——**命中结果与真实飞行等价**。

## 六、索敌层 `Targeting`

> 分帧总则:塔按 `EntityId.Index % 6` 分 6 帧轮转,每 **0.2 s** 重算一次完整权重;开火前只做一次 O(1) 的“目标仍有效”检查(存活 / 在射程 / `coef > 0`),不重排、不全量扫。

### 6.1 `DamagePreview`(权重里唯一的“能不能打”项)

- `Coefficient(packet, enemy)` = **护甲系数 × 衰减项 × 易伤 × 减伤**,复用 `DamageCalculator` 的乘区链,但**不应用状态、不取随机、不写统计**——它必须是纯函数,可在索敌里安全调用。
- 每个塔只用**自身默认弹种**算一次系数,不做“每发散射”复算。
- `coef == 0`(如低级穿甲打重型护甲)→ **权重 0,不选、不开火**;`InfiniteUntilLarge`(阳电子炮)打大型仍按 `×1.25` 计入。
- 目标状态(碎甲 / 热熔 / 低温)会改系数,所以**每轮索敌重算一次**(乘法级开销),不做跨轮缓存。

### 6.2 距离与权重公式

```
d      = max(1, |enemy.pos − muzzle.pos| − enemy.radius)      // 边缘距离
weight = coef × enemy.maxHp / d                                // 单体武器
weight = coef × (enemy.maxHp + cluster) / d                    // 爆炸武器(见 6.3)
```

- **用边缘距离而不是中心距**:大型半径 7.5,若按中心距,同样威胁下权重会被系统性压低 7.5;`d` 下限 clamp 到 **1**,避免贴脸时权重发散。
- **用最大生命而不是当前生命**:这是“高威胁优先”的设计意图;“快打死了还值不值得打”由 6.5 的预留表处理,**不污染公式本身**。
- 权重 clamp 到 `[0, 1e6]`;比较容差 `1e-4`,相等时按**当前生命降序 → `EntityId.Index` 升序**,保证确定性。
- 参与条件:`coef > 0` 且 `d ≤ range`;侦察外圈(射程 ×1.25)只喂给 `TurretMotor` 做预转向,**永不参与权重排序**。

### 6.3 爆炸武器的集群项

`cluster = min(2 × 目标最大生命, Σ 爆炸半径内其他敌人最大生命)`

- 走 `SpatialHash` 半径查询;统计上限 **32 个**,超出按 `平均值 × 数量` 外推,再整体 clamp——防止 500 敌人堆叠时权重爆掉。
- **只在爆炸半径 ≥ 3 的武器上启用**;`HitscanNearFuse`(高爆弹机枪分支)半径太小,查询开销不值,直接关掉。
- 结果按(塔, 目标)缓存 **0.2 s**,与索敌同周期;用该格敌人数量变化版本号粗失效。

### 6.4 三种策略的判定链(顺序即正确性)

**集中**(火箭 / 迫击炮 / 导弹 / 阳电子炮)
1. `coef > 0` 且 `d ≤ range`;
2. `reserved[id] < hp`(6.5 的预留表);
3. 取 `weight` 最大;
4. **开火条件 = 朝向到位**:`|angleDiff| ≤ aimTolerance`,`aimTolerance = max(2°, atan2(beamWidth/2, d))`(宽束自动放宽);未到位只转不开火,**不耗弹、不推进射速计时**。`aimTolerance` 由 `TowerDef` 给出:**垂发类(导弹发射井)`= 180°`**(任意朝向),无人机 `= 180°`(见 6.7)。

**扫射**(机枪 / 扫荡透镜 / 蜂窝)
1. 以“射程内最近的可杀伤目标”为朝向目标持续转向;
2. 每帧算**枪线**:当前朝向 ± 半束宽的射线/胶囊,取最近命中者;有则**立刻开火**,不等转到位;
3. 连续 **0.3 s** 未见枪线目标 → 停火(停火计时器只在“无枪线目标”时走);
4. 不设扇区、不预选目标。

**战略**(阳电子炮 / 导弹井斩首 / 雷暴):单发确认,每发离架做**一次**索敌,见 6.6。

### 6.5 逐发索敌与预留表(齐射 / 范围武器)

```csharp
// 齐射开始时 new,齐射结束或目标集合变化时清空;不跨齐射累计
reserved[targetId] += expectedDamage;   // 单体:damage × coef
                                        // 爆炸:damage × 半径内命中数 × coef
```

- 选目标时用 `hpLeft = hp − reserved[id]`;`hpLeft ≤ 0` → **本轮跳过该目标**。
- 若所有目标都 `hpLeft ≤ 0`,回到纯 `weight` 排序(允许溢出),保证**不空弹**。
- 只在 `集中` 生效;`扫射` 是“打到谁算谁”,不需要预留。
- 战略武器**不参与**预留(每次只发一发,溢出是“确保击杀”的设计意图)。

### 6.6 战略武器的三种模式

| 模式 | 选点方式 |
|---|---|
| 歼灭 | 候选点 = **8×8 粗密度网格**中“半径内敌人数量 × 平均威胁”最高的前 24 格,再做精算,按**实际可击杀数**排序;只在确认/自动锁定瞬间算一次 |
| 斩首 | 当前生命最高(大型天然最高);同生命按 `EntityId.Index` |
| 盘旋 | 以斩首目标为圆心、半径 = 射程 ×80% 的圆上游走;目标死亡后立即重选 |

- 粗密度网格可复用给 6.3 的集群项粗筛,不另建结构。
- 战略武器不参与 6.4 的 `扫射` 逻辑,也不维护 `reserved`。

### 6.7 无人机:精简索敌(无转向)

**删除的字段与逻辑**:`TurnSpeed`、`aimTolerance`、`gunLine`、`预转向`。无人机运行时**不挂 `TurretMotor`**;`TowerStatsBuilder` 不为无人机生成转向类 `StatKey`,`ModelValidator` 校验无人机塔的升级节点**不含 `TurnSpeed`**(写了也不生效,直接报错,避免设计表与实现脱节)。

| 项 | 精简后 |
|---|---|
| 开火条件 | `coef > 0 且 d ≤ droneRange` → **立即开火**,不检查朝向、不等计时 |
| 机枪(原 `扫射`) | 退化为**最近优先**:环查询取最近可杀伤目标;不维护“当前目标”,每轮重取 |
| 导弹(`集中`) | 按 6.2 权重选;爆炸半径 3 < 6.3 的门槛 → **不启用集群项**,省掉每架每轮的半径查询 |
| 查询 | 从自身所在格**逐圈外扩**查 `SpatialHash`,第一圈有候选即停(绝不扫全场 500);60 架 / 0.2 s 摊到 6 帧后每帧约 2 架 |
| 机头朝向 | 纯表现(`DroneView` 对目标 lerp),逻辑不读;因此“无需转向”不会看起来像倒着飞 |
| 雷达 | 只提供**移动坐标**,不提供攻击目标——索敌仍是无人机本地行为 |

> 净效果:无人机索敌从“转向 + 枪线 + 停火计时”三件事降为**一次环查询 + 一次乘法**,并与转向速度彻底解耦;固定塔仍保留 `TurretMotor`,因为它们的转向是玩法的一部分。

### 6.8 玩家接管接口(`ITargetProvider`,预留)

```csharp
public enum AimMode { Auto, Assisted, Manual }

public struct AimSolution { public Vec2 Point; public EntityId Target; public bool Valid; }

public interface ITargetProvider {
    // 返回 true = 本帧由外部接管;false = 回落到 6.2~6.5 的自动索敌
    bool TryResolve(in AimState state, in TowerRuntimeStats stats, out AimSolution sol);
}
```

- `TowerAgent` 每帧先问 `TowerAimController`;不能接管时走 `AutoTargetProvider`——**自动索敌一行不改,只是被整体替换**,不会出现两套并行逻辑。
- 三种模式:`Auto` = 纯 6.2~6.6;`Assisted` = 玩家只指定**目标**,提前量/枪线/开火时机仍由塔算(未来手操的推荐默认);`Manual` = 玩家指定**世界点**,允许打空。
- **接管不豁免任何既有规则**:仍受 `turnSpeed` 限制(不能瞬转)、仍吃 `fireRate` / 载弹 / 换弹、仍走 hitscan 与弹体原判定。
- `AimState{ mode, targetId, point, expireTick }`;**默认 3 s 无新指令自动回 `Auto`**,避免玩家切走 UI 后炮塔被锁死。
- 只在 `集中` / `战略` 上生效;`扫射` 保持自动(其定义就是“沿枪线自动清扫”,接管语义不成立)。
- 输入必须**命令化**:`AimCommand{towerId, mode, point|targetId}` 进 `CommandQueue`,鼠标坐标**永不直接进逻辑层** → 回放天然可复现。
- 同一接口也留给“雷达标记强制集火”这类技能,不新增代码路径。
- **依赖方向**:`AimState` 放在 `Targeting/`(纯结构体),`TowerAimController` 只写它——避免 `Targeting` 反向引用 `Entity` 造成循环。

### 7.3 无人机与移动工厂
- `DroneHangarController`:状态机 `Idle → Launching → OnField → Rearm(机库重装) → Refit(停机坪整备)`;**同时只有 1 个编队在线**;`容量 = 编队 × K`;战损过半才投放下一队;机枪/导弹/自爆三段弹药耗尽顺序(`导弹→机枪→自爆`)。
- `DroneAgent`:射程内**自动索敌**(机枪 = 最近优先 / 导弹 = 集中权重)、弹药、自爆;**无转向、无枪线、无预转向**——进入射程立刻开火(见 6.7);**不追击**——射程内有敌人就原地开火,只有「收到雷达坐标」且「射程内无敌人」才移动;断链原地待命但照常打射程内目标。
- `MobileFactoryController`:本体血量 3000、巡航拟合、活动半径 = 机库射程 ×200%、波次开始回停机坪、**20% 重创强制返航**、被击毁 → 12 范围爆炸 + 断连 + 300% 重建。
- `PatrolPlanner`:工厂的**移动决策**(自动拟合 / 玩家航点 / 召回),只管“去哪”,不管“打谁”——无人机索敌仍走 6.7(见 7.6)。
- `ThunderstormController`:雷暴的**空袭状态机 + 双条带投弹编排**,只产出“延时爆炸计划”,不生成弹体(见 7.5)。
- `StrategicWeaponController`:阳电子炮,**只在停机坪整备补满 8 发**;命中第一只大型即停。

### 7.4 命中与弹体(发射即判定)

| `delivery` | 武器 | 结算 |
|---|---|---|
| `HitscanLine` | 机枪、子弹类 | 发射瞬间线段判定;曳光 0.08~0.12 s 淡出 |
| `HitscanRect` | 激光、阳电子炮 | 胶囊判定;持续激光用**常驻 BeamView** |
| `HitscanNearFuse` | 高爆弹(**机枪塔分支**) | 交点前移 `fuseDistance` 后圆形爆炸 |
| `Chain` | 电弧 | 先算 3 跳,再画折线 |
| `Projectile` | **火箭塔全分支 + 迫击炮全分支 + 无人机** | 保留飞行体与真实飞行时间;抛射体带 z 轴弧线 |

- `ProjectileSystem` 服务全部飞行体;`Projectile` 字段:`pos, prevPos, dir, speed, lifetime, z, vz, template, ownerId`。
- **抛射体(迫击炮 / 子母弹)**:`trajectory = Arc`、`collideDuringFlight = false`——**只在 `z = 0` 落地时判定**,空中不撞敌人;落点按开火时的提前量算死,**不追踪**。
- **高度用闭式抛物线**:`u = t / T`、`z = 4H·u(1−u)`、`H = clamp(0.30 × 水平距离, 2, 12)`;**不做物理积分**——`T` 是玩法参数(由 `转向速度 → 弹速` 换算),交给重力会让射程、升级与 DPS 互相耦合。
- **落点指示**:开火时在落点画**收缩圈**,任何缩放级别都可读;弹体只承担表现,不承担信息。迫击炮弹体是简单几何体,**不做 LOD**。
- **空爆子母弹(自旋抛洒)**:母弹到点后进入 `Scatter` 状态——从 `h0 = 4` **一边下降一边自旋**,每 `Δt = 0.08 s` 甩出一批 `8 管 × 45°`,共 **4 批 = 32 颗**,抛洒总时长 0.24 s;载体每批自转 **11.25°**,4 批正好拼出 32 个均匀方向。母弹甩完即消失,**只生成、不结算伤害**。
  - 分布由**起始高度**与**抛洒间隔**直接决定,开火瞬间一次算完:`h_j = h0 × (1 − j/4)`、`r_j = R × √(1 − j/4)`(第 0 批最高、最远)、`θ = j × 11.25° + k × 45°`;`h0 / R / batches / tubes / interval / impactTime` 全部来自 `ProjectileDef.scatter`。默认 **`R = 6`**(覆盖直径 20),约束 `0.5R ≤ 4`——最内圈半径不能大于子弹头爆炸半径,否则瞄准点会被掏空;`R` 只改变 48 次命中在敌人间的**分布**,不改变总伤害。

    | 批次 j | 高度 | 半径 | 方向偏移 |
    |---|---|---|---|
    | 0 | 4.0 | `R` | 0° |
    | 1 | 3.0 | `0.87R` | 11.25° |
    | 2 | 2.0 | `0.71R` | 22.5° |
    | 3 | 1.0 | `0.50R` | 33.75° |
  - 子弹头用**水平直线插值 + 闭式抛物线 z** 飞向自己的落点,`z = 0` 时 `CircleHit(4)`;默认 **32 发同帧结算**:`τ_j = T_impact − jΔt`(`T_impact = 0.5 s`),视觉不变、伤害合并;若要“由内向外”的涟漪感,改用真实下落时长。
  - `引信优化` 只缩放 `Δt / τ`(整体时间),**不改 `R`**;`子弹头增量 32 → 40` 按 `5 × 8` 扩,`数量 ×0.75` 按 `3 × 8` 缩。
- **子母弹表现**:子弹头是**小几何点 + 短尾迹 + 地面影子**,抛洒过程可见;爆炸用 1 张大闪光 + 8~12 个小爆点合并表现,音效**每帧最多 3 声**,避免 32 连爆糊屏。
- **智能内爆**:同一落点的两段,不进弹体系统。
- **直射体(火箭 / 无人机)**:`trajectory = Direct`、`collideDuringFlight = true`,逐帧线段扫掠;蜂窝的 `homing = true` 负责跟踪曲线。
- 无人机是**实体**,碰撞对象只有**其它无人机与移动工厂等空中飞行器**;不与地面敌人碰撞,弹药耗尽自爆走**落点 AoE**;**空中单位单独用一个小列表(≤ 60 + 工厂 1)判定,不混入敌人空间网格**。
- 2.5D 下抛射体画**地面影子**提示高度;弹体一律用 **2D 贴图(朝向相机的 billboard quad)**,**不做 3D 模型**——按**屏幕空间速度方向**旋转,高度只体现在 `z` 偏移与影子;VLS 升空用缩放/换贴图表现,不引入第三个轴;`TracerBuffer` 环形复用(64~256 条),禁止每发 `new GameObject`;音效每帧限流。

### 7.5 雷暴:空袭投弹编排

**状态机**:`Idle → Takeoff → Run(10 s) → Return(10 s) → Refit`;一次空袭最多投 **16 + 2** 发,投完或窗口结束都**立刻返航**(文档“无论是否耗尽载弹都返航”)。

**判定形状:沿航线的矩形带(覆盖正下方)**

- 航线横穿敌潮(垂直于敌人推进方向);`f` = 航向,`n` = 法向,`P` = 机体位置。判定为**一条沿航线的矩形带**,以机体为界分左右两半(交替投弹用),**不设中轴死区**,正下方同样覆盖:

```
−Lb ≤ (Q−P)·f ≤ Lf      且      |(Q−P)·n| ≤ a1
```

| 参数 | 值 | 作用 |
|---|---|---|
| `Lf` 前向 | `1.0R` | 提前投弹距离 |
| `Lb` 后向 | `0.2R` | 小尾窗,避免刚掠过的目标漏掉 |
| `a0` 内缘 | **`0`** | 取消死区,`P` 正下方也在判定内 |
| `a1` 外缘 | `0.55R` | 单侧带宽 |

- **为什么用矩形而不是圆**:圆形随飞机移动,敌人在圆内停留 `≈ 2R / v`,单位时间投弹数固定 → 停得越久挨得越多;矩形随飞机前进,敌人只在“前向 + 尾窗”待 `1.2R / v`,离开即不再被投,天然限流。
- **为什么取消死区**:`P` 正下方就是敌潮中轴,漏掉它会让轰炸看起来“绕过敌人走”;原来的“防同一点连投”职责改由**同目标冷却 + 落点间距**承担(见下),不靠留洞。

**投弹节奏(按距离投弹,与巡航速度联动)**

```
Δs   = 0.5 × v_base ÷ 射速倍率        // 每飞行 Δs 距离投一发;基准速度下正好 0.5 s 一发
Δt   = clamp(Δs ÷ v_cruise, 0.15 s, 0.55 s)   // 0.55 = 10 s ÷ 18,保证窗口内投完
```

- **为什么按距离算**:飞行速度翻倍时,若仍固定 0.5 s,一发之间要飞过两倍距离,敌人在两发之间就被掠过了——“来不及投弹”。按 `Δs` 投弹后,**空间密度恒定**:飞得越快 → `Δt` 越短 → 同样的敌人挨同样多的弹。
- 下限 `0.15 s`(≥4 个逻辑帧,保证可读与冷却生效);上限 `0.55 s` 保证 18 发在 10 s 窗口内投完,**周期仍是 20 s**,不破坏 160 / 440 的口径。
- `射速` 词条作用在 `Δs` 上(每单位距离投更多);`巡航速度` 只改变 `Δt`。两者都动时以 `Δt` 的 clamp 兜底。
- 同一敌人冷却 **`max(2 × Δt, 0.4 s)`**——语义恒为“**绝不连续两发打同一点**”,并随速度自适应(飞得快时冷却同步变短)。
- 相邻落点最小间距 **`3.0`**(距离度量,与速度无关);不满足则改选次优目标。
- **左右条带交替**(偶数发左、奇数发右);某侧无合法目标则切另一侧;两侧都空 → **本发不扣弹**,下一 tick 再试(仅窗口结束时作废,保证 160 / 440 的数值口径成立)。
- 2 发重型(**400 / 半径 2 / 高级穿甲**)固定在**第 6、12 发**,不连发。
- `ModelValidator` 校验:`0.5 × v_base` 必须让基准 `Δt ∈ [0.2, 0.5]`;基准速度或载弹数改动后若越界,启动期直接报错。

**选点与结算**

- 选点 = 条带内 `weight`(复用 6.2,`d` 取到机体距离)+ **6.5 预留表**(只在**单次空袭内**累计,避免 18 发砸同一具尸体)。
- 提前量:`P_aim = P_enemy + v_enemy × T_delay`,`T_delay = 0.35 s`;预测点跑出矩形带则夹回带内。
- 投弹只登记 `ScheduledBlast{pos, radius, damage, packet, tick}`,到期在**第 7 步**按 `CircleHit(radius)` 结算——**不新增管线步骤,也不生成弹体**。
- 表现:落点先出现**收缩圈标记**,0.35 s 后爆炸(对应文档“不实现投弹动画,只出现爆炸”)。

**与词条的对应**:`射速` → 缩短 `Δs`(每单位距离投更多);`射击间隔` → 返航整备;`爆炸范围` → 炸弹半径;`射程` → `Lf / Lb / a1` 同比例放大;`载弹` → 16 / 2 数量;`巡航速度` → 只改变 `Δt`(见上),不改变空间密度;`留存率 / 阻滞力` 按文档 50% 折算进伤害与巡航速度,不进投弹逻辑。

### 7.6 移动工厂:巡航路线

**控制权优先级(高 → 低)**

1. `ForcedReturn` —— 重创 20% / 被击毁重建,**不可覆盖**;
2. `PlayerRecall` —— 玩家点“返航”;
3. `PlayerWaypoint` —— 玩家航点队列(**最多 3 个**);
4. `AutoPatrol` —— 自动拟合。

- 高优先级**抢占即清空**低优先级队列;波次开始按文档强制返航并清空航点。
- 处于重创返航时玩家指令**入队等待**(HUD 显示“待执行”),不打断紧急返航。

**自动拟合(`AutoPatrol`)**

- 频率:**1.5 s** 重算一次;当前点覆盖跌破 **40%** 时立即重算。
- 候选点:活动圆(半径 = 机库射程 ×200%,以所在空位为圆心)内 **8×8 网格**,剔除地图外与“距最近敌人 < `0.4 × 雷达半径`”的点。
- 评分:`score = 覆盖威胁 − 0.6 × 超时风险 − 0.25 × 位移代价`
  - 覆盖威胁 = 雷达半径内敌人 `maxHp` 之和(大型天然权重高);
  - 超时风险 = `max(0, 预计到达时间 − 8 s)`;
  - 位移代价 = `|candidate − current| ÷ 巡航速度`,抑制抖动。
- **滞回**:仅当 `score_new > score_cur × 1.2` 才换点,换点后 1.0 s 锁定;否则原地悬停(悬停零消耗)。
- 直线插值移动,空中单位忽略 `Blocked`;到达半径 `2` 视为到位。

**玩家指令(全部命令化)**

| 命令 | 效果 |
|---|---|
| `SetWaypointCommand{towerId, point, mode}` | `Replace` / `Append`(≤3)/ `Clear`;点被夹到活动圆内 |
| `HoldCommand{towerId, on}` | 驻守原地,不自动拟合,直到取消 |
| `RecallCommand{towerId}` | 目标 = 停机坪,到达即整备;整备结束后未驻守则恢复自动 |

- 到达航点默认**停留 4 s** 再恢复自动;`Hold` 打开则一直停。
- 玩家航点**不受安全约束**——可以为了雷达覆盖把工厂送进危险区;本体可被攻击正是这条分支的价格。
- **航线与炮塔解耦**:大舰巨炮的阳电子炮手动瞄准(6.8)不锁移动,移动也不打断瞄准,二者只共享本体位置。
- `PatrolPlanner` 是**唯一**写工厂目标点的模块;所有指令进 `CommandQueue`,回放可复现。

## 八、场景层 `Battle`

### 8.1 `BattleSimulation` 单帧管线(顺序即正确性)

```
1  CommandQueue.Drain()          建塔 / 升级 / 拆除 / 手动瞄准 / 暂停
2  WaveDirector.Tick(dt)         波次推进、布防暂停、每 5 波大型波、生成预算
3  StatusSystem.Tick(dt)         DoT、低温/碎甲/热熔到期、阻滞 0.2 s 清除
4  AuraSystem.Tick(dt)           光环与干扰(脏标记驱动,不每帧全量)
5  TargetingSystem.Tick(dt)      塔与无人机分帧索敌
6  FiringSystem.Tick(dt)         开火 → hitscan 立即结算 / 火箭·迫击炮生成弹体 /
                                 雷暴投弹只登记 ScheduledBlast(到期在第 7 步炸)
7  ImpactSystem.Tick(dt)         全部飞行体推进:直射体扫掠碰撞 / 抛射体落地判定 /
                                 ScheduledBlast 到期按 CircleHit 结算
8  MovementSystem.Tick(dt)       敌人推进(含减速/击退)、无人机机动、工厂巡航(PatrolPlanner)
9  ContactSystem.Tick(dt)        近战/远程对基地与工厂结算
10 DeathSystem.Flush()           分裂、金币、充电引爆、干扰驱散、统计累加
11 RebuildSpatialHash()          下一帧查询用(移动后重建一次)
12 PresentationSnapshot.Publish() 只读快照给表现层
```

**为什么先伤害后移动**:击退/减速当帧生效,避免“打完还能多走一帧”;**为什么死亡集中到第 10 步**:防止在第 7 步遍历中改数组,也保证分裂体不在同一帧被二次命中。**hitscan 在第 6 步就完成伤害**,同 tick 多塔按塔索引顺序结算,保证确定性与金币归属。

### 8.2 波次与生成
- `WaveDirector`:5 波一小轮;第 5 波**无母体**但按大型波结算奖励;中型从第 5 波、大型从第 10 波开始,`+50% / +50%` 每 5 / 10 波。
- `SpawnBudget`:**500 预生成上限**,只统计波次开始时预生成的敌人(分裂与投放不计入);复合子机在抽卡时权重接近中型。
  - 真实同屏峰值 = 500 + 分裂 + 投放,池与空间网格按 **800 峰值**预分配;超出时新生成排队,**不丢弃**。
- `SpawnPointResolver`:出生点 = **最远固定塔射程 + 缓冲**,只取固定塔,无人机库不参与;射程升级后实时外移。

### 8.3 经济与升级
- `EconomySystem`:击杀金币、局外货币即时入账、大型波三选一(伤害/金币/回血/上限/一次性金币)。
- `UpgradeService`:`cost = 基础价 × 系数 × (Lv−1)²`,唯一升级 ×1.25;拆除返还 `100% 基础价 + 50% 升级费`。
- `TowerStatsBuilder`:把 `TowerDef + UpgradeNodeDef[]` 重算成 `TowerRuntimeStats`(缓存 + 版本号),`BehaviorPatch` 在此替换行为类。

### 8.4 命令与快照
- 所有玩家操作 → `BattleCommand{ type, slot, targetId, position }` 入队,**布防暂停期才允许建造类命令**。
- `BattleSnapshot`:只读数组视图(位置/血量/状态/朝向),表现层据此插值,不允许反向写。

### 8.5 关卡初始化与波次投放

```
1  加载 MapDef → 校验 slots / base / 尺寸
2  注册五个库;按 delivery 预热 TracerBuffer(64~256 条)与敌人池(按 800 峰值)
3  建 RunState(baseHp, gold, goldMul, difficulty, seed)
4  布防暂停:只允许建造 / 升级 / 拆除,不生成敌人
5  布防结束 → 计算 SpawnBand 掩码(所有固定塔射程并集的补集,取最远塔)
6  Roll WaveRoster(seed = runSeed × 31 + waveIndex)
     - 数量 = min(500, base × 难度 × 波次系数)
     - 分裂体只挂 childTemplate,不占 500、不实例化
     - 大型投放不预生成
7  按名册 Rent 进 SpawnBand;放不下的进待投放队列(位置仍限制在射程外)
8  4 个时间档位:每档 25% 名册;解锁 = elapsed ≥ k × maxInterval 或 场上存活 ≤ 该档 30%
9  每 tick 先排空待投放队列,再进入 8.1 的 3~12 步
10 波次结束 = 名册全部生成 + 待投放队列为空 + 场上无存活
11 大型波奖励三选一 → 回到 4
```

- **SpawnBand 不是场外容器**:它是地图上“生成线 → 射程边界”之间的空带,敌人正常推进,只是**尚未进入固定塔射程**;无人机与移动工厂可以够到,这正是移动工厂的价值区。
- 生成带形状随**最远固定塔射程**变化,只在**布防结束时算一次**,战斗中不重算。
- **时间档位双轨触发**:后期永远是 4 波压力,每波更厚;清得快就提前进下一档,不会站着等计时。
- 名册的 roll 必须走**同一条种子 RNG 链**(名册 / 类型 / 投放 / 分裂),保证可复现。

## 十二、性能预算与约束

- 同屏上限:**500 预生成敌人(分裂 / 投放额外,峰值按 800 预分配)+ 60 无人机 + ~200 曳光 + 火箭/迫击炮弹体**;逻辑帧 `1/30 s` 目标 **< 4 ms**。
- 每帧**零分配**:所有临时数组走 `FreeList` / 栈上 `Span`;禁止 LINQ、禁止 `foreach` 装箱。
- 索敌分帧(6 帧轮转);光环/干扰用脏标记;空间网格每帧只重建一次。
- 命中以 **hitscan 线段/胶囊**为主,不靠提高帧率补;只有**火箭塔、迫击炮与无人机**按弹速真实飞行。
- 表现层不参与结算;所有伤害数字来自 `DamageStatsRecorder` 的累加,不做二次计算。

## 十三、局外成长与存档

### 13.1 `MetaSave`(磁盘结构)

| 字段 | 说明 |
|---|---|
| `version` | 存档格式版本;读档时按版本做**迁移**,不认识的版本拒绝加载并提示 |
| `currency` | 局外货币总量(**只增不减**,扣减走 `UnlockService` 的购买事务) |
| `unlockedIds[]` | 已解锁的塔 / 分支 / 起始资金档位 id |
| `stats` | 最高波数、累计击杀、累计场次(纯展示,不参与结算) |

### 13.2 `MetaSaveService`(原子写)

- **写盘流程**:序列化到 `meta.json.tmp` → `Flush` → 替换 `meta.json`(保留 `meta.bak`)→ 删 `tmp`;任何一步失败都保留旧存档,不产生半截文件。
- **读档流程**:优先读 `meta.json`,校验失败(损坏 / 版本过高)回退 `meta.bak`,两者都坏则**新建空存档**并提示,不崩溃。
- **提交时机**:`Commit()` 只在“进入 `RunEnd` / 主动退出 / 应用失焦”三处触发,避免战斗中逐次写盘;`RunState.metaCurrencyEarned` 在局内是**内存累计**。
- **单人本地存档**:不涉及网络校验;**不做数值校验回滚**(这不是竞技游戏),但会校验 `currency >= 0` 与 `unlockedIds` 均存在于 `UnlockDef`,越界条目直接丢弃。

### 13.3 `UnlockService`

- `CanBuy(id)`:货币足够 + 前置 `prereqIds[]` 全部已解锁 + 未重复解锁。
- `Buy(id)`:一次性扣费并写入 `unlockedIds`;扣费与写入在**同一个内存事务**里,随后立即 `Commit()`,失败则整体回滚。
- 输出只给**可选集合**(`HashSet<string>`),被 `RunSetup` 用来过滤建造面板与升级面板——**局外成长不修改任何数值**(详见 17.4)。
- 局外货币的产出:`RewardService` 在**大型波**结束时按 `RewardDef`/`DifficultyDef` 给一笔大额,普通波按小比例给;两者都写 `RunState.metaCurrencyEarned`,**即时入账,不依赖本局胜负**(文档“局外货币即时入账”)。

## 十四、应用流程与场景

**场景流**:`Boot → MainMenu → RunSetup → Battle → RunEnd` → 回 `MainMenu`。五个场景常驻对象:

| 场景 | 常驻 | 职责 |
|---|---|---|
| `Boot` | `GameBootstrap` | 加载 `ModelDatabase`(全部 JSON)+ `ModelValidator` 硬校验 + `MetaSaveService.Load()`;校验失败直接停在错误页,不带病进游戏 |
| `MainMenu` | — | 展示局外货币、已解锁内容、开始新局 |
| `RunSetup` | `RunController`(DontDestroyOnLoad) | 选难度、查看本局种子;把 `difficultyId + seed + 已解锁集合` 写进 `RunState` |
| `Battle` | `RunController` | 创建 `BattleSimulation`,驱动 `SimRunner`;结束时把结果交给 `RunEnd` |
| `RunEnd` | `RunController` | 结算**局外货币**(已在局内即时累加,这里只做展示与落盘) |

- `RunController` 是**单局唯一持有者**:持有 `RunState{seed, difficulty, unlockedSet, metaCurrencyEarned}` 与 `BattleSimulation`;场景切换不重建它,因此暂停/倍速/回放不跨场景丢失。
- **局外货币即时入账**:每次 `RewardService` 判定获得货币时,先写进 `RunState.metaCurrencyEarned`,**离开战斗(胜/负/退出)时统一 `MetaSaveService.Commit()`**;中途崩溃最多丢本局未提交部分,不影响已有存档。
- `SceneFlow` 只负责 `LoadScene` 与加载遮罩,**不含任何游戏规则**;`BattleSimulation` 从不感知场景或 UI。
- `PauseController` 归属 `App`:它决定 `SimClock` 是否推进(暂停 / 1× / 2×),并表示“当前处于布防暂停”——`InputRouter` 靠这个状态决定建造类命令是否合法。
- 一局结束的判定只有两条:`BaseHp <= 0`(失败)或玩家主动退出;**无限波数,不以波数结束**。

## 十五、输入 / 相机 / UI

### 15.1 `InputRouter`(Unity 输入 → 命令,单向)

| 操作 | 产生 | 合法时机 |
|---|---|---|
| 点空位 | `BuildCommand{slotIndex, towerId}` | 仅布防暂停 |
| 点已有塔 | 打开升级面板(纯 UI,不产生命令) | 任意(战斗暂停时也能看) |
| 点升级节点 | `UpgradeCommand{towerId, nodeId}` | 仅布防暂停 |
| 拆除 | `DemolishCommand{towerId}` | 仅布防暂停 |
| 手动瞄准某塔(接管) | `AimCommand{towerId, mode, point/targetId}` | 任意(暂停中亦可) |
| 工厂设置航点 / 驻守 / 召回 | `SetWaypointCommand` / `HoldCommand` / `RecallCommand` | 任意 |
| 战略武器选点 | `StrategicStrikeCommand{weaponId, worldPos}` | 暂停中亦可(`thought.md`:暂停可操作战略武器) |
| 倍速 / 暂停 | `SetSpeedCommand` | 任意 |

- **规则全部在 Battle 侧复检**:`InputRouter` 只做射线拾取与命中测试,不判断金币、不判断是否布防期;非法命令由 `CommandQueue` 丢弃并回一条拒绝事件(UI 提示),保证“UI 不写逻辑”。
- **帧内顺序**:所有命令在 `BattleSimulation` 的第 1 步统一消费,因此同一帧内“拆除 + 重建”按**提交顺序**结算,不会出现半帧状态。
- **拖拽预览不产生命令**:`BuildGhostView` 只读 `SlotGrid` 与射程数据画幽灵,松手才发 `BuildCommand`。

### 15.2 `CameraController`

- **固定 15~20° 俯角、正交投影**,只允许**缩放**(正交尺寸范围对应“看清单个敌人 ↔ 看清整条 80×120 战场”),**禁止旋转、禁止自由俯仰**——2.5D 的高度表达依赖固定视角,一旦可旋转,影子与 billboard 朝向全部要重做。
- 相机平移夹在**地图包围盒 + 边距**内,不允许看到地图外;缩放到最远时整张图可完整入镜。
- 相机只影响**表现**(可见性剔除、曳光可见长度);**不影响任何逻辑判定**——射程、索敌、生成带全部在世界坐标里算,不随缩放变化。
- 不做 LOD:迫击炮弹/导弹低细节,任何缩放下都用同一套几何体 + billboard。

### 15.3 UI 面板(全部只读快照)

| 面板 | 数据来源 |
|---|---|
| `HudBinder` | 波数、基地血量/上限、金币、局外货币(本局累计)、当前速度 |
| `UpgradePanelBinder` | `TowerRuntimeStats` 的**基础数据 + 当前伤害倍率 + 升级后对比**三项,不显示 DPS |
| `RewardPanelBinder` | 大型波结束后的五选三(按 `RewardDef` 生成,含已叠加层数预览) |
| `StatsPanelBinder` | 后期统计窗口:伤害总量与占比 |
| 敌人详情(暂停) | 血量、护甲等级、四项衰减、携带增益/减益、当前状态层数 |

- UI **不读实体内部字段**,只读 `BattleSnapshot`(`EnemySnapshot / TowerSnapshot`);快照每逻辑帧结束发布一次,UI 在 `LateUpdate` 消费,避免 UI 与逻辑互相踩状态。
- 所有文本走**同一套格式化**(`DamageFormat`):基础值/倍率/升级后统一保留规则,避免三处各写一套四舍五入。

## 十六、表现与音频细则

| 项 | 规则 |
|---|---|
| 曳光(hitscan) | `TracerBuffer` 环形池 **64(默认)~256(上限)**;一条曳光 = 起终点 + 0.08~0.12 s 淡出;同帧超过池容量时**丢弃最旧**的,不扩容、不分配 |
| 激光束 | `BeamView` **每座激光塔常驻一个**(不是每帧新建);开火时拉长到命中点,停火时缩放为 0;命中闪白靠材质参数,不换对象 |
| 闪光/穿透 | 命中点一个小闪光 + 穿透时沿路径保留 0.05 s 的残段;每帧最多新增 **8** 个 |
| 爆炸 | 池化圆环 + 缩放;子母弹 32 发**共用 1 个批次音效**,视觉上允许合并同一位置的爆点 |
| 影子 | `ShadowView` 由 `Projectile.z` 驱动:**偏移 = z × 固定方向系数**,缩放 `1 / (1 + z × k)`,透明度随 z 下降;地面无 z 的实体不画影子 |
| 弹体 | 一律 2D billboard(按屏幕空间速度方向旋转);高度只体现在 z 偏移与影子 |
| 受伤/死亡 | 受伤闪白 0.05 s;**不显示伤害飘字**;死亡直接缩放到 0 + 一个小碎片环 |
| 音效 | 每帧最多 **4 个** SFX;优先级 `爆炸 > 战略武器 > 重装/导弹 > 常规射击`;同类音效 0.05 s 内只播一次(合并);循环音(激光、无人机蜂鸣)用**单实例 + 参数调制**,不叠加 |
| 音频与逻辑 | `AudioDirector` 只消费 `BattleSnapshot` 与事件,**不反向影响逻辑**;所有音量走总线(主/战斗/UI) |

- 表现层**不做二次结算**:命中判定、伤害数字、死亡时点全部来自逻辑帧事件;表现只负责“在正确的位置、正确的时间、按正确的时长画出来”。
- 所有特效**不允许阻塞逻辑帧**:同一帧的事件先入队,`VfxDirector` 在表现层按预算(见上表)逐帧消费,超预算的丢弃而不是排队堆积。

## 十七、难度 / 奖励 / 地形 / 解锁数据

### 17.1 `DifficultyDef`(只改三项)

| 字段 | 说明 |
|---|---|
| `hpGrowthPerWave` | 敌人生命值**随波次增长的速度**(文档“难度”第一项) |
| `goldRate` | 金币获取率(第二项) |
| `mediumShare / largeShare` | 中型 / 大型敌人**占比**(第三项) |
| `startGold / rewardMul` | 起始资金与奖励倍率:作为**该难度的基准值**,不引入第四类难度维度 |
| `smallBase / smallStep / smallStepEarly` | 小型敌人基准数量:前 `earlyGrowthWaves`(默认 10)波用 `smallStepEarly`,之后回落到 `smallStep`;只影响**数量** |
| `metaRate` | 局外货币倍率 |

> `WaveRules` 同步新增 `earlyGrowthWaves`(小型提速的波数上限)与 `waveClearGold`(每波清场固定金币,再乘 `goldRate`)。

> 硬约束:难度**不得**修改护甲、衰减、阈值、移速、射程等任何“身份数值”;`ModelValidator` 校验 `DifficultyDef` 只有上述字段,防止难度悄悄变成第二套数值表。

### 17.2 `RewardDef`(大型波三选一)

| `kind` | 叠加方式 |
|---|---|
| `DamageBonus` | **加算**(每次 +X% 加到同一乘区) |
| `GoldRate` | **加算** |
| `BaseHeal` | 立即治疗,不叠加 |
| `BaseMaxHp` | **固定数值加成 + 边际递减**:第 n 次选择收益 `= perPickValue / (1 + dimStep × n)`,`dimStep` 入表可调 |
| `GoldBurst` | 一次性金币,不叠加 |

- 三选一由 `RewardService` 从**五项**中抽 3 个不重复项;同一项可被多次选中(受上表叠加规则约束)。
- 奖励只写入 `RunState` 的**局内乘区表**(`RunModifiers`),**不写入** `MetaSave`——局外只解锁,不改数值。
- 第 5 波“只有数量扩容、没有母体”的大型波**照常触发三选一**(文档明确),`WaveDef.isLargeWave` 为唯一触发条件,不判断是否出现母体。

### 17.3 地形 `TerrainTag`

| tag | 影响 |
|---|---|
| `Open` | 无影响 |
| `NoBuild` | 该格不可作为塔位(`SlotGrid` 生成时剔除) |
| `Slow` | 进入该区域的敌人移速乘区(值在 `MapDef.terrainParams`,与状态系统分开结算) |
| `Blocked` | 不可通行,推进时绕行(仅用简单避让,不做寻路) |
| `Elevated` | 提供视线高度,忽略 `Blocked` 对枪线的影响 |

- 地形只影响**移动与建造**,不影响伤害;**不引入高低差命中修正**(2.5D 的 z 只用于抛射表现,不做真实高度对抗)。

### 17.4 `UnlockDef`(局外解锁)

- `kind`:解锁**起始塔种类 / 升级树分支 / 初始资金档位**;`cost` 为局外货币;`prereqIds[]` 做前置链。
- **解锁只决定“可选集合”,不修改任何数值**:`UnlockService` 输出的是一份 `HashSet<string>` id 集合,`RunSetup` 用它过滤建造面板与升级面板;`ModelValidator` 强制 `UnlockDef` **不含 `StatModifier`**,从数据结构上杜绝“解锁 = 变强”。
- 初始资金档位是**可选起始值**(如 300 / 400 / 500),选定后写进 `RunState.startGold`,局内经济仍按正常公式走。

## 十八、确定性与回归

### 18.1 三条互不干扰的随机流

| 流 | 用途 | 是否必须确定 |
|---|---|---|
| `logic` | 波次名册、档位划分、生成点、投放落点、分裂子代类型 | **必须** |
| `combat` | 命中/散射、暴击类判定、导弹末段抖动 | **必须** |
| `vfx` | 曳光抖动、碎片方向、音效变体 | 不需要,但**不得回读**逻辑流 |

- 三条流各自 `Rng(seed + streamSalt)`,**禁止共享一个 RNG 实例**;`vfx` 流绝不参与逻辑,`logic` 与 `combat` 的消耗顺序必须与执行顺序一致(遍历顺序固定为 `EntityId.Index` 升序)。
- 核心层禁用 `UnityEngine.Random`、`Time.deltaTime`、`Physics`;所有查询遍历**有序**(排序键 `Index`,同 Index 不可能同时存在——`Generation` 保证唯一性)。

### 18.2 `ReplayRecorder`

- 记录:`seed`、`difficultyId`、`unlockedSet`、**按 tick 排列的命令日志**(`BattleCommand` 的紧凑二进制序列化)。
- 回放 = 同参数重建 `BattleSimulation` + 逐 tick 重放命令;`SimHarness` 与游戏跑**同一份**逻辑代码,保证“离线结论 = 线上表现”。
- 每 **1 秒**写一个**状态哈希**(敌人数量/总血量/金币/基地血量的 64 位混合),用于快速定位第一处分叉的 tick。

### 18.3 回归测试

- `DeterminismTests`:同一 seed + 同一命令日志跑两遍,最终哈希一致;再跑第三遍**打乱 vfx 流**,哈希仍一致(验证表现随机没泄漏进逻辑)。
- `ReplayTests`:录制 30 波命令日志 → 回放 → 与录制时的逐秒哈希完全一致。
- `RewardTests`:五选三抽取、加算/边际递减、第 5 波无母体仍发奖。
- `MetaSaveTests`:原子写(写临时文件 → 替换)、损坏存档回退到上一份、货币只增不减。
- **黄金测试**:固定 3 组 seed(初期/中期/后期),断言“第 N 波结束时敌人数量、塔伤害总量、基地血量”在容差内;数值调整后若超容差,必须显式更新黄金文件并说明原因。
- **浮点确定性边界**:当前只用 `float` + 基础四则/`sqrt`,同类构建内可复现;**跨平台(ARM/x86)不保证**——若将来需要跨平台回放,再把 `Vec2` 换成定点数(接口不变,`MathUtil` 内切换)。

### 21.5 结论

**可以进入编码。** 剩余未知全部是**数值**而非**结构**:所有规则都有唯一模块落点,数值集中在 JSON,调整不需要改代码。

**三个必须盯住的风险**(不是设计问题,是实装问题):

1. **2.5D 抛射观感**——billboard + 影子是唯一需要美术侧验证的部分,建议 M2 第一个切片就做“迫击炮 + 影子 + 落点圈”。
2. **无人机与 500 敌人分离**——空中单位保留独立小列表,绝不混入敌人网格;这条要在 M2 开工前写成断言。
3. **跨平台浮点**——当前只承诺同构建可复现;若将来要跨平台回放,`Vec2` 内部换定点数,接口不变。
